# SanoraWorks search, answer, and discovery research

Reviewed: 17 November 2026. Audience: businesses and startups searching in international English. Primary brand: SanoraWorks; monitor Sanora separately because it may include unrelated intent. This is qualitative page and search-intent research, not measured keyword demand, difficulty, ranking position, or a promise of indexing, rankings, leads, or AI citations.

## Evidence and limitations

The source baseline is main commit 7c9f4a6: eleven existing public pages, server-rendered copy, canonical metadata, robots.txt, and sitemap. Four commercial service intents previously lived at one URL. Existing artwork and development notices are retained. The release adds four dedicated service URLs for fifteen public marketing/legal pages.

Searches reviewed on 17 November 2026: “web development agency business websites customer portals services”; “product engineering services MVP development startups”; “AI workflow automation services enquiry documents”; “cloud deployment DevOps services startups monitoring”. Results and the linked primary business pages support separating these buying intents; they do not establish volume or difficulty. GR8R Studio presents product engineering as a distinct offer; Artificial Workflow describes repeatable work and review paths; Startwyse gives cloud operations its own service page. These observations inform topic separation only; their claims, delivery times, clients, prices, and results are not adopted.

Ranking, search volume, keyword difficulty, backlinks, indexed-page counts, Core Web Vitals field data, organic clicks, impressions, CTR, and average position: **unavailable**, not zero. Search Console and Bing Webmaster access are not connected in this session. No visitor analytics scripts are added.

[Google AI search guidance](https://developers.google.com/search/docs/appearance/ai-features) says ordinary SEO practices apply, with no special AI files or schema required. [Google’s updates](https://developers.google.com/search/updates) record that FAQ rich results stopped appearing on 7 May 2026. Buyer questions remain useful content; there is no FAQ-snippet promise.

## Priorities

P0: shared public content, dedicated services, canonical/404 safety, read-only public interfaces, negotiation, and access boundaries. P1: home, services navigation, project and company context, metadata, breadcrumbs, policies reflecting the new public interfaces, mobile and accessibility review. P2: routine terms presentation and measurement follow-up. DNSSEC/DS and webmaster account work depend on suitable access and must not be marked passed without live evidence.

The shared model in src/data/public-content.ts composes the existing service/project/site data. Page copy, absolute browser titles, descriptions, H1s, page JSON-LD, REST, MCP and negotiated Markdown use it. Reusable service/project/process sections retain the underlying data sources. Organization and WebSite have stable apex @ids, Sanora is an alternate brand name, and pages reference those identities. Services use Service; unfinished projects use CreativeWork with In development status. BreadcrumbList describes the visible hierarchy. No reviews, clients, locations, prices, or launch promises are invented.

The sitemap includes exactly fifteen marketing/legal pages. Utility documentation, catalog, REST, Markdown index, MCP and registry are excluded and carry noindex response headers. Known-page lookup is an allowlist; it does not read filesystem paths or fetch arbitrary URLs. Existing private PDFs remain untracked and are not copied into public assets, links, APIs, resources, or the sitemap.

## Discovery references and interpretation

- [RFC 8288](https://www.rfc-editor.org/rfc/rfc8288): append Link relations without replacing existing preloads.
- [RFC 9727](https://www.rfc-editor.org/rfc/rfc9727.txt): application/linkset+json with its registered profile, linking real endpoints and descriptions.
- [Official MCP web-standard serving](https://ts.sdk.modelcontextprotocol.io/v2/serving/web-standard): official fetch-native handler, a fresh server per request, stateless compatibility.
- [Cloudflare Markdown for Agents](https://developers.cloudflare.com/fundamentals/reference/markdown-for-agents/): plan-specific native offering; this repository uses its own Worker wrapper and keeps the Free plan.
- [Cloudflare robots preferences](https://developers.cloudflare.com/bots/additional-configurations/managed-robots-txt/): managed directives can be prepended; live robots must be inspected for contradictions. Content Signals state preferences rather than enforcing access.
- [DNS-AID draft 00](https://datatracker.ietf.org/doc/html/draft-mozleywilliams-dawn-dnsaid-00): evolving November 2026 work in progress. Publish standard SVCB transport parameters, and put unregistered discovery parameters in TXT fallback. Only implemented MCP is advertised. The JSON organization registry uses an organization-owned format, not an invented DNS-AID standardized schema.
